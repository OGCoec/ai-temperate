# 生成视频下载按钮设计

## 目标

仅为 AI 回复中的已生成视频增加 H5 下载按钮。图片展示、图片上传进度、视频预览、视频 OSS 上传和后端接口均保持现状。

## 已确认决策

- 复用视频附件现有的 `attachment.url`，不新增后端下载接口。
- 浏览器使用 `fetch → Blob → Object URL → a[download]` 完成保存，避免跨域 OSS 链接忽略 `download` 属性后只打开视频。
- 下载按钮位于视频播放器下方右侧，使用现有绿色视觉体系、下载图标和“下载视频”文字。
- 每个视频附件独立维护下载中状态；同一视频下载期间禁止重复点击。
- 下载失败时显示“视频下载失败，请重试”，不自动打开新窗口，也不影响播放器继续播放。
- 只针对 `AVAILABLE` 且 `contentType` 以 `video/` 开头的 AI 回复附件；图片和用户输入视频不增加按钮。

## 组件与状态

继续在 `fornted/components/user/workspace/user-chat-panel.vue` 中渲染按钮，不新建组件。当前需求只有一个按钮和一个短生命周期状态，拆分组件会增加不必要的传参和文件数量。

组件新增一个以 `attachmentId` 为键的内存下载状态集合。状态不写入会话消息、不写入本地存储，也不影响现有 `mediaUploadProgressByKey`。

## 下载流程

```text
用户点击“下载视频”
→ 校验附件 AVAILABLE、video/*、HTTPS URL
→ 将 attachmentId 标记为正在下载
→ fetch(attachment.url)
→ 校验 HTTP 响应成功
→ response.blob()
→ URL.createObjectURL(blob)
→ 创建临时 a[download] 并触发点击
→ 删除临时元素并 URL.revokeObjectURL
→ 清除下载中状态
```

下载文件名优先使用附件的 `fileName`。文件名为空或不以 `.mp4` 结尾时，回退为 `generated-video.mp4`，避免把 OSS Object Key 暴露给用户。

## 交互与无障碍

- 默认文案为“下载视频”，下载图标仅作装饰并设置 `aria-hidden`。
- 下载中显示“正在下载”，按钮 `disabled`，并设置 `aria-busy="true"`。
- 按钮可通过键盘聚焦，使用现有绿色焦点样式。
- 窄屏时按钮仍位于媒体卡片下方，不覆盖播放器控制条，也不改变视频最大宽 `720px`、最大高 `1080px` 的约束。

## 错误与资源释放

- 网络失败、非 2xx 响应、Blob 创建失败或浏览器下载触发失败统一显示“视频下载失败，请重试”。
- `finally` 始终清除下载中状态。
- 临时 Object URL 在点击后释放；组件卸载时补充释放仍未清理的 URL，避免页面长时间使用产生内存泄漏。
- 错误提示不包含 OSS URL、对象 Key、响应正文或其他敏感信息。

## 测试范围

新增前端契约测试，约束以下行为：

- 下载按钮只出现在 AI 回复的可预览视频分支，不出现在图片分支。
- 点击路径调用专用视频下载方法，并复用 `attachment.url`。
- 实现包含 `fetch`、`Blob`、Object URL 创建与释放。
- 下载中按钮禁用且文案切换为“正在下载”。
- 失败提示固定为“视频下载失败，请重试”。

第一阶段只编写测试和业务代码，不运行测试、构建或部署。用户明确授权第二阶段后，再执行该契约测试和现有聊天前端测试。
