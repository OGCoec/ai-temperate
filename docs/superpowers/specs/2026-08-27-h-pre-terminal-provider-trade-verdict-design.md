# H-PRE 退款终态流水裁决设计

## 目标

H-P1 与 H-PR 仍按 `TERMINAL_OUTCOME` 裁决：本机调度错过计划毫秒落点不直接失败，只要服务端接住全部回调并收敛到合法终态即可通过。

## 根因

退款兜底完成后，业务会清空 `membership_order.provider_trade_no`，同时在 `membership_payment_callback.provider_trade_no` 保留第三方流水作为支付事实。现有验收 SQL 在识别回调终态前统一要求订单流水非空且与回调一致，因而把正确的 `REFUND_REQUIRED` 终态误判为失败。

## 裁决规则

- 所有模式继续检查订单、用户、回调、状态版本、到期时间和硬关闭时间的一致性。
- 回调流水必须始终非空、格式合法且带当前分组前缀。
- 所有 `APPLIED` 终态要求订单流水与回调流水一致。
- 所有 `REFUND_REQUIRED` 终态要求订单流水已经清空，以证明退款兜底完成。
- H-A1、H-AR 及其他严格分组保持原有服务端时间裁决。

## 验证边界

更新 PowerShell 契约测试，使其同时约束回调流水前缀、应用分支流水匹配和退款分支流水清空。根据项目两阶段交付规范，本次只交付代码，不自动执行测试或压测。
