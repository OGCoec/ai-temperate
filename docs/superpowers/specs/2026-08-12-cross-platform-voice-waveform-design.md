# Android 与 H5 共用 PCM 实时波形设计

## 1. 背景

语音输入区目前在状态行左侧显示“正在聆听”，右侧显示录音时长，中间保留了可用于展示实时音频反馈的空间。现有录音链路已经在 Android 与 H5 之间建立统一边界：两端最终都向 `user-chat-panel.vue` 提供 `16 kHz / 单声道 / PCM16 little-endian` 的 `ArrayBuffer` 音频帧，再由同一个回调把音频发送到语音 WebSocket。

本设计在该统一 PCM 边界上增加只读的本地音量分析旁路，并用同一个 Canvas 组件在 Android App-Plus 与 H5 上绘制实时波形。波形不得创建第二条录音链路，也不得影响、阻塞或改变现有音频传输。

## 2. 目标

- Android 与 H5 使用相同的 PCM 输入、音量算法、波形状态和绘制规则。
- 状态行形成“状态文字 / 实时波形 / 计时”的稳定三段布局。
- 波形必须由真实麦克风 PCM 驱动，禁止使用与声音无关的随机动画模拟。
- 录音音频发送优先于可视化；波形异常时语音录制和上传仍须继续。
- 在最长 5 分钟录音期间保持固定内存占用，不保存历史 PCM。
- 屏幕阅读器只感知语音状态，不播报每根柱子或每秒计时。
- 遵守系统的减少动态效果偏好。

## 3. 非目标

- 不修改 Java 后端、Whisper、本地语音识别服务或 WebSocket 消息格式。
- 不修改 Android `AudioRecord` 与 H5 `AudioWorklet` 的采样率、声道数和网络帧大小。
- 不增加第二个麦克风、第二个 `AudioRecord` 或第二个 `getUserMedia`。
- 不把音量级别或波形历史发送到服务器、日志或监控系统。
- 不提供频谱图、音调识别、说话人识别或服务端 VAD 可视化。

## 4. 已确认的现有边界

### 4.1 H5

`fornted/common/voice/voice-recorder-h5.js` 使用 `getUserMedia` 和 `AudioWorklet` 获取音频；`fornted/static/voice/pcm16-worklet.js` 将输入重采样为 16 kHz 单声道 PCM16，并以 1600 个采样为常规帧输出。常规帧时长为 100ms，停止时允许输出不足 1600 个采样的尾帧。

### 4.2 Android

`fornted/uni_modules/ait-voice-recorder/utssdk/app-android/index.uts` 使用 `AudioRecord` 直接获取 16 kHz 单声道 PCM16，每次最多读取 1600 个采样。帧经 Base64 跨 UTS 边界后，在 `fornted/common/voice/voice-recorder.js` 中恢复为长度受控、偶数字节的 `ArrayBuffer`。

### 4.3 共用入口

`fornted/components/user/workspace/user-chat-panel.vue` 的 `recorder.start(frame => ...)` 是两端 PCM 汇合点。波形分析从该回调旁路接入，现有 `session.sendAudio(frame)` 仍是主路径。

## 5. 方案选择

采用“共用 PCM 分析器 + 共用 Canvas”方案。

不采用 H5 `AnalyserNode` 与 Android 原生音量回调各自计算的方案，因为两端会形成不同的采样窗口、增益映射、平滑参数和维护路径。不采用 CSS 随机波形，因为它无法反馈麦克风是否真正接收到声音。

## 6. 总体架构

```text
Android AudioRecord / H5 AudioWorklet
                │
                ▼
      16 kHz mono PCM16 ArrayBuffer
                │
                ▼
        recorder.start(frame)
          │                 │
          │                 └──► PCM 波形分析器
          │                           │
          ▼                           ▼
   session.sendAudio(frame)     5 个 20ms 音量值
          │                           │
          ▼                           ▼
   语音 WebSocket               波形数据包（10Hz）
                                      │
                                      ▼
                                Canvas 渲染器
```

音频发送必须先入队，波形分析随后同步完成；禁止等待波形绘制或动画结果后再发送音频。波形分析或绘制异常采用 Fail Open：清空可视化并显示静音基线，不能取消语音会话。

## 7. 模块边界

### 7.1 PCM 音量分析器

新增 `fornted/common/voice/voice-waveform-envelope.js`，作为无 UI、无平台依赖的纯计算模块。

职责：

- 只读解析 little-endian PCM16；禁止修改调用方传入的 `ArrayBuffer`。
- 把每个常规 1600-sample 帧拆成 5 个 320-sample 窗口，每个窗口代表 20ms。
- 对停止时的合法尾帧按实际采样数生成 1 至 5 个音量值。
- 计算 RMS、Peak、分贝映射、噪声门和 Attack/Release 平滑。
- 返回受控的 `0.0` 至 `1.0` 音量数组与下一次计算所需的平滑状态。
- 对空帧、奇数字节、非 `ArrayBuffer` 或计算异常返回空音量数组，不得抛出可中止录音的异常。

建议的逻辑接口：

```text
analyzePcm16Envelope(frame, previousState)
  -> { levels: number[], nextState }
```

分析器不得访问 Vue 实例、Canvas、WebSocket、系统时间或平台 API，以便同一组输入在 Android 与 H5 上获得相同输出。

### 7.2 波形组件

新增 `fornted/components/user/workspace/user-voice-waveform.vue`，负责布局内的 Canvas 容器、生命周期、无障碍属性和平台一致的视觉输出。

职责：

- 接收包含会话 epoch、递增序号和 1 至 5 个音量值的小型波形数据包。
- 将音量值放入有上限的待绘制队列和历史环形缓冲区。
- 根据 Canvas 实际宽度、柱宽和间距动态计算可见柱数。
- 录音时启动 `requestAnimationFrame`，其他状态不持续占用绘制循环。
- 尺寸变化时重建 Canvas 像素尺寸并保留最新可见历史。
- 会话 epoch 改变、组件卸载、录音取消或错误时立即清空队列。
- Canvas 设置 `aria-hidden="true"`，不成为独立可访问节点。

组件可以延续现有 `user-thinking-orb` 的 Canvas/RenderJS 边界。逻辑层每约 100ms 只传递一个包含最多 5 个数字的数据包；RenderJS 在视图层按 20ms 节奏消费这些值，避免让 Vue 响应式系统以 50 至 60Hz 更新数组。

### 7.3 页面编排

`user-chat-panel.vue` 负责：

- 为每次语音会话初始化独立的分析器状态和波形序号。
- 在 `session.sendAudio(frame)` 已请求入队后调用分析器。
- 只在当前 `voiceSessionEpoch` 仍有效时发布波形数据包。
- 把当前语音状态、减少动态效果偏好和数据包传入波形组件。
- 在停止、取消、错误、页面隐藏、组件卸载和会话替换时重置波形。

页面不得把历史 PCM 放入 Vue `data`，也不得在日志中输出 PCM、音量数组或完整波形数据包。

## 8. 音量算法

### 8.1 分窗

- 输入采样率固定为 16000 Hz。
- 默认窗口为 320 samples，即 20ms。
- 常规 1600-sample 帧生成 5 个窗口。
- 合法尾帧最后一个不足 320 samples 的窗口按实际样本数计算。

### 8.2 能量计算

每个窗口分别计算：

```text
rms  = sqrt(sum(sample²) / sampleCount)
peak = max(abs(sample))
mixed = 0.8 × rms + 0.2 × peak
db = 20 × log10(mixed + epsilon)
```

Peak 只占 20%，用于保留爆破音和短辅音的瞬态反馈；RMS 占 80%，避免波形因单个峰值剧烈闪动。

### 8.3 映射与平滑

第一版使用固定参数，避免自适应噪声底在不同设备上反复漂移：

- 噪声门起点：`-52 dB`。
- 可视上限起点：`-12 dB`。
- 归一化结果限制在 `0.0` 至 `1.0`。
- 归一化后使用约 `pow(value, 0.7)` 的视觉压缩，让正常说话在小高度区域仍有可见变化。
- 音量上升使用 `0.65` Attack，快速跟随说话。
- 音量下降使用 `0.20` Release，避免柱高抖动和突然坠落。

这些数值是明确的第一版调校基线；只有真实设备对比表明 Android 与 H5 观感存在系统性偏差时，才允许调整。平台不得各自使用不同常量。

## 9. 渲染与时间调度

现有音频帧每约 100ms 到达一次。若一次把 5 根柱子全部加入历史，画面会以 10Hz 成组跳动；若每帧只生成一根柱子，动态又过于迟钝。因此采用下列调度：

- 数据包到达后立即把最多 5 个音量值放入视图层队列。
- RenderJS 从第一个值开始，每 20ms 消费一个值。
- `requestAnimationFrame` 负责绘制和相邻高度插值，不负责决定录音时长。
- 待绘制队列最多保留 15 个值，即约 300ms。
- 队列超限时丢弃最旧的可视化值并追上最新声音；只允许丢可视化值，禁止影响音频发送。
- 连续 250ms 没有新音量值时，当前柱高平滑回落到静音基线，不生成随机波形。

历史只保存归一化音量值。历史容量按以下方式计算：

```text
visibleBars = floor(canvasCssWidth / (barWidth + barGap))
```

窗口缩小时裁掉最旧历史；窗口放大时不回填已经丢弃的历史数据。

## 10. 视觉规格

### 10.1 状态行布局

现有 `.voice-inline-status` 调整为稳定三列：

```text
状态文字 | 可伸缩波形 | 固定计时
```

建议使用：

- 列宽：`max-content minmax(48px, 1fr) max-content`。
- 列间距：手机端 8px，宽屏端 12px。
- 状态行最小高度：28px。
- 计时继续使用 `font-variant-numeric: tabular-nums`。
- 极窄宽度下首先减少可见柱数，不截断状态文字和计时。

### 10.2 波形

- Canvas CSS 高度：24px。
- 柱宽：2px。
- 柱间距：3px。
- 最小柱高：2px，并使用圆头形成静音点。
- 最大柱高：20px。
- 柱子以垂直中心线为中心同时向上、向下增长。
- 新柱子从右侧进入，历史向左移动。
- Canvas 设备像素比最高按 2 处理，避免高分屏浪费 GPU 和内存。

### 10.3 颜色

- 静音点：`rgba(174, 185, 179, 0.35)`。
- 普通音量：`#aeb9b3`。
- 较强音量：`#75dfb7`。
- 高音量上限：`#37d39a`。

颜色随归一化音量平滑插值，不允许按阈值突然闪烁。波形不能使用比输入文字更高的持续视觉优先级。

## 11. 状态行为

### 11.1 REQUESTING_PERMISSION / ISSUING_TICKET / CONNECTING / QUEUED

- 组件保持占位，显示静态点状基线。
- 不使用随机波形冒充真实输入。
- 计时仍按现有规则，仅在真正进入 `RECORDING` 后开始。

### 11.2 RECORDING

- 使用真实 PCM 音量驱动。
- 现有 40px `user-thinking-orb` 保持布局占位但暂停连续动画，避免页面同时出现两个高频运动焦点。
- 状态文字和计时保持稳定，不随柱高变化移动。

### 11.3 FINALIZING

- 停止接收新音量值。
- 已显示波形在 180ms 内回落到点状基线。
- 计时停止，状态文字切换为现有“正在生成最终文字”。

### 11.4 IDLE / ERROR / 取消 / 会话替换

- 立即停止绘制循环。
- 清空待绘制队列、历史环形缓冲区和平滑状态。
- 新会话不得显示上一会话的任何波形。

## 12. 无障碍与减少动态效果

- Canvas 为装饰内容，设置 `aria-hidden="true"`。
- 状态容器保留当前 `role="status"` 与 `aria-live="polite"`，但只在状态变化时更新可访问文本。
- 计时更新不得触发屏幕阅读器每秒播报。
- 音量、高度和波形历史不得写入可访问名称。
- 启用减少动态效果时停止横向滚动插值，将可视更新降低至每秒 4 至 5 次；仍保留真实音量反馈，但不使用持续流动动画。

## 13. 性能、资源与隐私

- 音量计算量约为每秒 16000 个采样的简单数学运算，不创建逐样本对象。
- 计算模块复用固定长度数值缓冲区；Canvas 历史使用固定容量环形缓冲区。
- 任何时刻都不保存完整历史 PCM，不上传、不持久化波形数据。
- `requestAnimationFrame` 只在需要绘制时运行；页面不可见、录音结束或组件卸载时必须取消。
- 可视化错误不得向语音 WebSocket发送额外消息，不得改变提交、取消或重试语义。
- 日志只允许记录受控错误码，例如 `VOICE_WAVEFORM_RENDER_FAILED`，禁止记录 PCM、音量数组、设备名称或可推导说话节奏的数据。

## 14. 错误处理

- PCM 分析失败：当前数据包丢弃，显示静音基线，语音发送继续。
- Canvas 获取失败：隐藏波形区域但保留状态文字与计时，语音发送继续。
- 绘制队列积压：丢弃最旧可视值，保留最新可视值，音频队列不受影响。
- 尺寸为 0：暂停绘制；恢复可见尺寸后从最新值继续，不补画旧数据。
- 旧 epoch 数据：无条件丢弃，禁止污染新会话。

## 15. 测试设计

第一阶段可以编写但不得自动执行测试；进入用户批准的第二阶段后再按确认范围运行。

### 15.1 纯计算测试

- 全零 PCM 生成全零音量。
- 正弦波、固定幅值与接近满量程输入映射到受控范围。
- 正负样本对称输入得到相同音量。
- 常规 1600-sample 帧生成 5 个值。
- 合法尾帧生成正确数量的值。
- 空帧、奇数字节和错误类型 Fail Open，不抛出中止录音的异常。
- Attack 快于 Release，且所有输出都在 `0.0` 至 `1.0`。
- Android 与 H5 对同一 PCM fixture 产生完全相同的数值结果。

### 15.2 组件契约测试

- 状态行包含状态、波形、计时三列。
- 只有当前 epoch 的数据包会进入组件。
- RECORDING 启动绘制，FINALIZING 回落，IDLE/ERROR 清空。
- 队列不会超过 15 个待绘制值，历史不会超过可见柱数。
- 减少动态效果模式降低更新频率。
- Canvas 不暴露逐帧无障碍信息。
- 组件卸载后不存在活动计时器或动画帧。

### 15.3 真机与浏览器检查

- Android App-Plus 真机正常音量、安静环境、较大音量和快速说话。
- H5 Chrome/Edge 的 HTTPS 环境使用相同语音样本观察映射一致性。
- 窄屏手机、宽屏 H5、横竖屏切换和系统字体放大。
- 连续录音 5 分钟时内存保持稳定，音频传输不因波形绘制出现丢帧或排队增长。

## 16. 验收标准

- Android 与 H5 使用同一个分析模块和同一个波形组件。
- 波形随真实麦克风音量变化，静音时回落为点状基线。
- 正常帧在视觉上按 20ms 节奏连续展开，不出现每 100ms 五根柱子成组跳动。
- 从声音采集到可见反馈的常规延迟不高于约 120ms。
- 波形异常、Canvas 不可用或队列积压时，录音、WebSocket 音频发送和最终转写仍正常工作。
- 最长录音期间历史数组和待绘制队列均有固定上限。
- 状态文字与计时位置稳定，窄屏不发生覆盖。
- 新语音会话不会显示旧会话的波形。
- 未修改后端协议、录音参数或平台权限流程。

## 17. 实施顺序

1. 编写纯 PCM 音量分析模块及其测试代码。
2. 编写共用 Canvas 波形组件及组件契约测试代码。
3. 在 `user-chat-panel.vue` 的统一 PCM 回调中接入旁路分析，并补充会话 epoch 清理。
4. 把状态行调整为三列布局，并在 RECORDING 时暂停原有 Orb 的连续动画。
5. 在获得用户第二阶段验证授权后，运行约定的前端测试与 Android/H5 真机检查。
