# AI 生成图片双边界等比适配设计

## 目标

AI 回复中的生成图片必须同时受到最大宽度和最大高度限制。原图任意一边先达到上限时，整张图片按原始宽高比缩小；不得裁剪、拉伸或强制放大小图。用户上传图片缩略图、视频和普通文件卡片保持现状。

## 尺寸规则

- 桌面端图片最大宽度为 `1080px`，并且不得超过消息容器可用宽度。
- 图片最大高度为 `min(70vh, 1080px)`，避免长图占据过多连续滚动空间。
- 原图小于宽高上限时按原始尺寸展示，不主动放大。
- 实际缩放系数采用 `min(1, 最大宽度 / 原图宽度, 最大高度 / 原图高度)`。
- 图片保持居中展示；横图、竖图和方图使用同一套规则。

## 前端实现

生成图片继续使用 uni-app `image` 组件。图片加载完成后读取原始宽高，根据当前视口高度计算允许宽度，再通过 `widthFix` 让高度随最终宽度保持原始比例。窗口尺寸变化时使用已保存的原始宽高重新计算，组件卸载时注销尺寸监听。CSS 继续提供 `max-width: 100%`，确保窄屏或消息容器比计算上限更小时进一步等比缩小。

自然尺寸只保存在组件内存状态中，以附件稳定标识作为键；不修改后端附件协议，不向 URL 或日志写入尺寸数据。预览图片替换为最终 OSS 图片后，按新附件重新计算。

## 边界与失败处理

- 加载事件缺少有效宽高时，不执行计算，回退到容器宽度自适应。
- 无法取得视口高度时使用 `1080px` 高度上限。
- 计算结果至少为 `1px`，避免异常元数据生成无效样式。
- 仅调整 AI 回复中的图片，避免影响用户上传附件的固定缩略图行为。

## 覆盖准备

更新现有聊天页契约测试，静态确认生成图片具备加载尺寸处理、双边界缩放公式、`widthFix` 等比模式和容器宽度兜底，同时确认用户上传缩略图仍使用 `aspectFill`。根据项目分阶段规范，本次第一阶段只编写测试代码，不执行测试、构建或打包。
