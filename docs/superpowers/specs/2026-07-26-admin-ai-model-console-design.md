# 管理端 AI 模型控制台前端设计

## 目标与边界

本功能为 `myuniappadmin` 增加完整的 AI 模型管理界面，并使用现有管理员统一请求封装访问 `/api/admin/ai-models`。界面覆盖分页查询、新增、详情查看、并发安全编辑、单个启停和批量启停。

模型主记录不提供物理删除。界面中的业务“删除”统一表达为“停用”，批量删除统一表达为“批量停用”；停用后仍可重新启用。前端不得出现 `DELETE /api/admin/ai-models/**` 请求，也不得伪造数据库级删除行为。

本功能保持现有管理员安全边界：Cookie Scope、PreAuth、WebRTC、风险 Challenge、CSRF、管理员 Session 和统一错误恢复全部继续由 `admin-http.js` 处理。页面和 API 模块不得直接调用 `uni.request` 绕过该请求层。

## 方案比较与确定方案

### 方案 A：移动端卡片列表、独立新增页、独立详情编辑页

列表负责搜索、筛选、排序、分页和批量启停；新增与详情编辑使用独立页面。Android 使用单列卡片，宽屏 H5 使用信息密度更高的列表行，但两端共享同一数据模型和交互语义。

优点是移动端触控清晰、表单不会挤在弹窗里、路由可以直接表达当前模型，且编辑冲突能够保留完整上下文。缺点是页面数量较多。

### 方案 B：列表页加底部抽屉

新增和编辑都在底部抽屉中完成。优点是切换快；缺点是复杂表单、能力多选、键盘和安全区容易拥挤，Android 返回行为也更难保持一致。

### 方案 C：列表页内联展开编辑

点击卡片后在原位置展开表单。优点是路由最少；缺点是分页、批量选择和编辑状态相互干扰，长列表中定位不稳定。

采用已经确认的方案 A。它最符合现有管理端的独立页面结构，也能让 Android 和 H5 各自获得合适的信息密度。

## 路由与页面

新增三个管理端路由：

- `pages/ai-models/index`：分页列表、服务端搜索、状态过滤、排序和批量启停。
- `pages/ai-models/create`：新增模型。
- `pages/ai-models/detail`：查看详情、进入编辑模式、保存字段和单个启停。

三个页面均使用自定义导航栏和现有管理端主题，不共享普通用户前端页面。列表跳转详情时只在 URL 中携带 11 位 Base64URL `publicId`，不携带模型名称、倍率、能力或 ETag。

详情页默认只读。管理员明确点击“编辑”后才显示可编辑控件；状态启停与字段保存保持为两个独立动作，避免修改倍率时意外改变启用状态。

## 视觉系统与响应式布局

页面复用 `common/app-theme.scss`：

- 页面背景：`#080b0d`
- 内容表面：`#10161a`
- 抬升表面：`#141d22`
- 主青色：`#39d6d2`
- 辅助青色：`#69d4e2`
- 管理端主要提交动作继续使用现有强调色
- 危险或冲突提示使用现有低饱和红色

Android 列表使用单列模型卡片。每张卡片依次展示模型名称、厂商、启用状态、输入倍率、输出倍率、最多三个能力标签和详情入口。能力超过三个时显示“+N”，不把全部能力挤进卡片。

宽屏 H5 使用同一语义的紧凑列表行，不使用需要横向滚动的超宽表格。倍率数字使用等宽数字特性，状态使用圆点加文字，不能只依赖颜色。

所有触控目标至少 44px，按钮在按下时立即反馈。状态过渡保持在 150–250ms，并为 `prefers-reduced-motion` 提供无位移动画的替代。页面不使用装饰性循环动画、渐变文字或与现有后台不一致的玻璃卡片。

## 列表查询与分页

列表顶部按以下顺序排列：

1. 页面标题和“新增模型”主操作。
2. 模型名称或厂商搜索框。
3. 启用状态、排序优先级、排序方向和每页数量。
4. 当前结果总数与批量管理入口。
5. 模型列表。
6. 上一页、页码信息和下一页。

查询状态包括：

- `pageNum`：从 1 开始。
- `pageSize`：20、50 或 100，默认 50。
- `keyword`：模型名称或厂商关键字；去除首尾空白，空值不发送。
- `enabled`：全部时不发送，启用发送 `true`，停用发送 `false`。
- `sortPriority`：`INPUT_FIRST` 或 `OUTPUT_FIRST`。
- `direction`：`ASC` 或 `DESC`。

排序文案必须组合成人类可理解的四种表达：

- 输入倍率优先 · 从低到高
- 输入倍率优先 · 从高到低
- 输出倍率优先 · 从低到高
- 输出倍率优先 · 从高到低

搜索输入使用短延迟防抖；改变关键字、状态、排序或每页数量后回到第一页。翻页请求进行期间保留现有结果并显示轻量加载状态，避免列表整体闪烁。响应返回的 `total/pages/hasPrevious/hasNext` 是分页按钮的唯一依据。

当前后端列表 API 已支持分页和倍率排序，但尚未支持 `keyword` 与 `enabled`。正式接入时必须把这两个条件实现为服务端查询参数；禁止只过滤当前页并把结果伪装成全局搜索。

## 列表选择与批量操作

批量模式开启后才显示选择框。选择集合只保存当前页面可见模型的 `publicId`，翻页、改变查询条件或刷新结果时清空，防止对不可见模型执行操作。

底部批量操作栏展示选中数量、取消、批量启用和批量停用。没有选中模型时启停按钮禁用。批量停用使用明确确认对话框；批量启用不使用危险确认，但仍显示提交状态。

请求执行期间锁定重复提交。成功后清空选择并重新加载当前页；如果停用导致当前筛选页变空，则回退到仍存在数据的上一页。失败时保留选择，显示可恢复错误，不自动重复写请求。

## 新增模型

新增页字段与现有 `POST /api/admin/ai-models` 保持一致：

- `modelName`
- `description`
- `icon`
- `tags`
- `vendor`
- `inputRatio`
- `outputRatio`
- `enabled`
- `capabilities`

表单分为“基本信息”“倍率配置”“模型能力”和“初始状态”四组。能力从 `CHAT_COMPLETIONS`、`RESPONSES`、`IMAGE`、`VIDEO`、`AUDIO` 中选择，至少一项。标签最多 20 个，由可删除的标签项表达，不发送未规范化的空标签。

创建期间提交按钮显示加载状态并禁止重复提交。创建成功后使用响应中的 `publicId` 进入详情页；失败时保留全部输入，并把字段错误显示在对应字段附近。

## 详情、编辑与 ETag

详情页通过 `GET /api/admin/ai-models/{publicId}` 取得完整字段与 `ETag`。API 请求层必须同时返回响应数据和 ETag，页面不得自行根据 `rowVersion` 猜测请求头。

编辑模式维护“服务器快照”和“当前草稿”。保存时只构造实际变化字段的 JSON Merge Patch：

- 省略字段表示保持不变。
- `description` 或 `icon` 显式清空时发送 `null`。
- `capabilities` 发生变化时发送完整新集合。
- `enabled` 不进入 Patch。

请求使用：

```text
Content-Type: application/merge-patch+json
If-Match: <详情 GET 返回的强 ETag>
```

保存成功后替换服务器快照、草稿和 ETag，并退出编辑模式。空 Patch 不发送请求。

发生 `409 AI_MODEL_VERSION_CONFLICT` 时保留当前草稿，显示“模型已被其他管理员更新”，提供“查看最新内容”。重新加载前必须明确告知管理员未保存草稿不会自动覆盖最新版本。

缺少或非法 ETag、模型不存在、名称冲突和字段校验错误分别显示可理解文案，不把内部异常对象或响应体原样呈现。

## API 请求层

新增独立 `common/admin/admin-ai-model-api.js`，只能依赖现有管理员请求封装。该模块负责：

- 安全拼接分页查询参数。
- GET 列表。
- GET 详情并读取 ETag。
- POST 新增。
- PATCH Merge Patch。
- PATCH 单个状态。
- POST 批量状态。

页面不得重复拼路径、CSRF Header 或错误恢复逻辑。所有请求继续经过现有 `admin-http.js`，从而复用 Cookie Scope、PreAuth、WebRTC、Challenge、管理员会话和一次性错误恢复。

API 模块不提供删除方法，也不调用 `uni.request`。模型名称、描述、标签和能力不写入 URL、LocalStorage 或 SessionStorage。

## 后端列表查询补充边界

为了让搜索和状态过滤在分页总数上正确，列表 API 增加可选参数：

```text
keyword=<模型名称或厂商关键字>
enabled=true|false
```

关键字为空时不参与查询；非空关键字在 Service 中规范化，并通过参数化 SQL 查询模型名称或厂商。状态为空表示全部。分页、COUNT、排序和能力批量加载仍由现有 PageHelper 流程负责，不产生 N+1。

该补充不改变详情、新增、编辑、启停、缓存和词元回填逻辑。

## 状态与错误体验

列表、新增和详情分别拥有独立的加载、空数据、失败和提交状态：

- 首次加载使用与最终布局一致的骨架，不使用全屏旋转图标。
- 空列表说明当前筛选没有模型，并提供“重置筛选”或“新增模型”。
- 网络失败保留当前内容并提供手动重试。
- 管理员 Session、PreAuth、WebRTC、Challenge 和 Block 继续交给统一请求层处理。
- 写请求成功使用无焦点抢占的状态提示；失败信息使用 `aria-live`。

页面离开时若存在未保存编辑，必须确认是否放弃；只读详情和未修改新增表单不弹出无意义确认。

## 测试边界

第一阶段随实现新增不连接外部服务的契约测试，锁定：

- 三个路由和自定义导航栏存在。
- API 模块全部通过管理员统一请求层发起请求。
- 列表参数、排序映射、分页和服务端搜索/状态过滤正确。
- 查询条件变化回到第一页，翻页或筛选变化清空选择。
- 单个和批量启停使用现有状态接口。
- 前端不存在模型删除请求或删除按钮文案。
- 新增请求字段完整。
- 详情读取 ETag，编辑发送 Merge Patch 与 `If-Match`。
- 空 Patch 不发送，版本冲突保留草稿。
- Android 触控尺寸、移动布局、宽屏布局和 reduced-motion 样式存在。

后端补充测试锁定 `keyword/enabled` 与 PageHelper COUNT、排序和能力批量查询的组合行为。
