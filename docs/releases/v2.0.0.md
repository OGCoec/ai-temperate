# ai-temperate v2.0.0 第二版发布说明

发布日期：2026-07-27

## 版本定位

第二版是在远程 `origin/main` 的首版认证系统基础上进行的一次大型功能扩展。首版已经具备普通用户注册、登录、找回密码、会话刷新、单端与多端退出，以及 RabbitMQ 验证码可靠投递；第二版重点补齐管理员业务、AI 模型管理、网络风险控制、对象存储和边缘网关能力。

本版本的源码范围包括 Java 后端、普通用户 uni-app、管理员 uni-app、PostgreSQL SQL、Redis Lua、Cloudflare Worker、自动化测试代码和运维文档。

## 核心新增功能

### 1. 完整管理员系统

- 增加独立的管理员注册、登录、会话和安全配置模块。
- 支持首位管理员初始化、管理员状态查询和一次性注册流程。
- 管理员注册支持 hCaptcha、邮箱验证码和手机验证码。
- 支持管理员密码登录、会话 Bootstrap、当前管理员信息查询、单端退出和全部设备退出。
- 管理员使用独立的 Cookie、CSRF、流程凭证、Redis Key、设备绑定和限流边界。
- 管理员 H5 使用独立域名 `admin.niko000o.site`，不与普通用户前端共享页面路由或认证 Cookie。

### 2. AI 模型管理

- 增加 AI 模型分页列表、详情、新增和字段编辑。
- 支持按模型名称或厂商搜索，并按启用状态、输入倍率和输出倍率筛选排序。
- 支持单个及批量启用、停用；模型停用后保留主记录，不提供物理删除。
- 支持模型能力集合的批量维护，并与模型主记录处于同一个 PostgreSQL 本地事务。
- 使用 11 位 Base64URL 公共 ID，禁止向管理端暴露数据库内部 ID。
- 使用强 ETag 和 `rowVersion` 乐观锁防止并发编辑覆盖。
- 增加启用模型 Redis 快照、事务提交后刷新和模型搜索 Token 回填。

### 3. AI 模型图标库

- 支持上传本地模型图标到阿里云 OSS。
- 支持验证并登记外部 HTTPS 图标地址，外部图片不会复制到 OSS。
- 支持图标分页、详情、创建、编辑、文件替换和删除。
- 一个图标可被多个模型复用；仍被模型引用时禁止删除。
- 支持 PNG、JPEG/JPG、WebP、GIF、ICO、AVIF 和安全 SVG，单文件最大 2 MiB。
- 对真实格式、像素、动画帧、ICO 条目、Content-Type 和累计解码成本进行服务端校验。
- 对外部地址执行 HTTPS、公网 DNS、重定向、响应状态、大小和 SSRF 安全检查。
- 为 OpenAI、Anthropic、Google、xAI、DeepSeek、智谱、Moonshot 和 Alibaba/Qwen 官方 SVG 提供受限兼容档位；可信来源仍必须通过 CSS、引用和内嵌图片安全校验。

### 4. 网络风险控制

- 增加普通用户和管理员独立的 PreAuth 预认证凭证。
- 增加网络风险评分、观察、Challenge 和 Block 决策。
- 增加 Cloudflare WAF Challenge 联动及挑战完成、挑战失败、封禁页面。
- 增加 WebRTC 本地 IP 探测、报告校验和出口网络一致性检查。
- 增加 IP2Location、IPing 外部 IP 情报 Provider、Provider Registry 和 Redis 缓存。
- 增加 IP HMAC 隐私保护，Redis Key、日志和指标不保存明文 IP。
- 增加 IP2Location API Key 的加密保存、批量导入、分页查询和批量删除。
- 增加风控指标、低敏结构化日志、Trace ID、超时、降级和回滚配置。
- Refresh Session、CSRF 与 PreAuth 通过 Redis Lua 原子校验和续期，防止部分状态被单独刷新。

### 5. 普通用户头像

- 增加头像预上传、取消预上传和上传确认接口。
- H5 通过预签名 PUT 直接上传阿里云 OSS，应用不向浏览器暴露永久凭据。
- 增加头像真实格式、尺寸、大小和对象元数据校验。
- 用户资料增加头像状态和公开头像地址。
- 临时对象与正式对象使用独立 OSS 前缀，并提供临时对象生命周期清理要求。

### 6. Cloudflare API Gateway

- 增加同时服务 `niko000o.site` 和 `admin.niko000o.site` 的同源 API Worker。
- 普通用户域名只允许普通认证 API，管理员域名只允许管理员 API，禁止跨 Host 混用。
- Worker 将允许的 `/api/**` 请求原路径转发到 `api.niko000o.site`。
- Worker 与 Spring Boot 使用独立 HMAC 密钥签名边缘请求，防止伪造外部 Host、客户端 IP 和边缘身份头。
- 生产业务 Cookie 改为 Host-only，并提供旧父域 Cookie 迁移和清理机制。
- 增加 Worker 部署、分阶段切换、回滚和网络风险上线文档。

### 7. 人机验证统一化

- 将普通用户 Turnstile 重构为统一的 `HumanVerificationService` 策略接口。
- 通过 Registry 同时管理 Turnstile 与 hCaptcha 实现。
- 普通用户注册、验证码登录和找回密码继续使用 Turnstile。
- 管理员注册和登录使用 hCaptcha。
- hCaptcha 默认连接和响应超时为 8 秒。
- 增加供应商错误分类、超时分类、hostname/action 绑定、低敏日志和指标。

### 8. 认证、会话与前端安全升级

- 普通用户登录、注册、找回密码和 Session Refresh 接入 PreAuth 与风险校验。
- 增加 Cookie 作用域迁移、Host-only Cookie 和普通端/管理员端隔离。
- 增加 WebRTC 失败页、风险挑战页和封禁页。
- 增加统一的前端密码、邮箱、手机号和国家地区校验模块，普通端与管理员端复用。
- 增加请求 Trace、异步分派幂等保护、受控错误分类和敏感信息脱敏。
- 移除仅用于本地演示的认证 UI Preview 会话旁路。

### 9. PostgreSQL、Redis 与可观测性

- 新增 `ai_model_capability` 和 `ai_model_icon` 表。
- 扩展 `ai_model` 的厂商、倍率、状态、描述、搜索 Token、图标逻辑关联和行版本字段。
- 增加模型搜索、前缀查询、启用状态和逻辑关联索引。
- 增加模型能力与图标的孤儿数据检查 SQL，不引入物理外键。
- 扩展统一 `RedisKeyFactory`，覆盖管理员、PreAuth、网络风险、模型缓存和会话绑定。
- 对邮箱、手机号、IP、流程凭证和敏感配置使用 HMAC 或加密保护。
- 增加管理员、AI 模型、网络风险、头像和人机验证的指标与结构化日志。

## 首版已经具备并在第二版继续保留的能力

以下能力并非第二版从零新增，而是在第二版中继续复用或增强：

- 普通用户注册、密码登录、邮箱/手机验证码登录。
- 找回密码和密码重置后撤销全部 Refresh Session。
- Session Refresh、Bootstrap、单端退出和全部设备退出。
- RabbitMQ Publisher Confirm、持久化消息、手动 ACK/NACK。
- 有限次数延迟重试、终态失败消息和终态/死信队列。
- 消息幂等、发送流程状态机和 Provider 失败分类。
- 普通用户 Cloudflare Turnstile；首版远程代码中的默认连接和读取超时已经是 8 秒。
- PostgreSQL、Redis、RabbitMQ、Cloudflare Tunnel 和本地 HTTPS 基础设施。

第二版对消息系统的主要扩展是增加 `ADMIN_REGISTRATION` 验证用途，并让管理员注册复用已有的可靠投递状态机；RabbitMQ ACK、延迟重试和终态队列主体在首版中已经存在。

## 部署注意事项

- 管理员 H5、普通用户 H5、API 和 Cloudflare Worker 必须分别部署到规定的 Host，不得互换路由。
- 上线前必须配置管理员 hCaptcha、Edge Proxy HMAC、网络风险 HMAC、IP2Location、OSS 和现有验证码供应商所需 Secret。
- 已创建过旧版 `ai_model` 相关空表的环境，需要按数据库文档确认是否重建 `ai_model_capability` 和 `ai_model_icon`。
- 生产环境禁止提交真实密码、Token、AccessKey、验证码、证书私钥或 Cloudflare Tunnel 凭据。
- 网络风险应按照 `DISABLED`、`OBSERVE`、`ENFORCE` 的受控阶段逐步启用，并保留回滚能力。
- 普通站点与管理员站点切换为 Host-only Cookie 后，应按迁移文档清理历史父域 Cookie。

## 验证状态

本次第二版提交遵守项目的两阶段交付规则：先提交代码，再由用户确认第二阶段安全测试范围。

本次发布整理没有运行编译、单元测试、集成测试、依赖树分析、安全扫描，也没有连接 PostgreSQL、Redis、RabbitMQ、Cloudflare、OSS 或验证码供应商。本文只说明源码中已经包含的模块和设计边界，不将“代码已提交”表述为“功能已经验证通过”。

进入第二阶段前，应由用户明确确认拟运行的命令、隔离环境、测试范围和允许写入的外部状态。
